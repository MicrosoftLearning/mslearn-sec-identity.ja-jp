# ラボのセットアップ

次のステップに従って、ラボのシナリオに必要な環境を構築してください。

1. **Azure portal** (`https://portal.azure.com`) を開きます。

1. **User1** の管理者の役割でログオンします。

1. **検索**バーで、「**カスタム テンプレートのデプロイ**」を検索して開きます。
   
1. **[Build your own template in the editor] \(エディターで独自のテンプレートをビルド\)** を選択します。

1. メニューで、**[ファイルの読み込み]** を選択します。

1. デスクトップ フォルダーからファイル **lab-4d-setup.json** を選択します。

1. **[保存]** を選択します。

1. **[確認と作成]** を選択します。

    > **注**: デプロイが完了するまで数分かかる場合があります。

1. ブラウザーを閉じます。

# Defender for Cloud のセキュリティ態勢と CSPM について確認する

組織には、単一の結果を超える態勢の更新が必要です。 リーダーが知りたいこと:

- 現在のセキュア スコアとトップ リスク ドライバー。
- 名前付きフレームワークに対するコンプライアンス状態。
- 承認されたシークレット ストアの外部でシークレットが露出されるかどうか。
- 誰がいつまで修復を所有するのか。

このラボでは、Defender for Cloud を使用して、推奨事項の優先順位付け、コンプライアンス マッピング、シークレット スキャン、ガバナンスの割り当て、攻撃パスのレビューを使用してセキュリティ態勢を評価して実行します。

このラボでは、次のことを行います。

- セキュア スコアと主要な推奨事項のシグナルを記録します。
- NIST SP 800-53 Rev. 5 コンプライアンス コントロールを割り当ててレビューします。
- CSPM シークレット スキャンの結果を調査します。
- 安全でないシークレットの配置を正しい Key Vault の使用と比較します。
- 攻撃パスの分析をレビューします。
- 所有者と期限を含むガバナンス ルールを割り当てます。
- 必要に応じて、マルチクラウド コネクタのスコープをレビューします。

この演習の所要時間は約 **75** 分です。

> **注**: このラボは、事前に設定された Defender for Cloud の調査結果と環境内の推奨事項に依存しています。

---

## 構成済み状態をレビューする

1. Azure portal で、**[リソース グループ]** を開き、**sc500-lab4d-rg** を選択します。

1. 次のリソースが存在することを確認します。

    - **sc500-lab4d-storage**
    - **sc500-lab4d-webapp**
    - **sc500-lab4d-kv**
    - **sc500-lab4d-vm**

1. **[Microsoft Defender for Cloud]** を開き、サブスクリプションにアクティブな態勢データが表示されていることを確認します。

---

## セキュア スコアと上位の推奨事項をレビューする

1. [Azure portal](https://portal.azure.com) に **User1** アカウントでサインインします。

1. 「**Microsoft Defender for Cloud**」を開きます。

1. **[概要]** で、以下を記録します。

    | フィールド | 値 |
    |-------|-------|
    | セキュア スコア (%) | |
    | 異常なリソース数 | |
    | アクティブな推奨事項の数 | |

1. **[推奨事項]** を開きます。

1. **[最大スコアの影響]** で並べ替えます。

1. 影響が最も大きい推奨事項を開き、影響を受けたリソースと修復ガイダンスをレビューします。

1. 非破壊的なクイック修正が利用可能な場合は、それを適用します。

---

## 規制コンプライアンスを割り当ててレビューする

1. Defender for Cloud で、**[規制コンプライアンス]** を開きます。

1. **[標準の追加]** を選択します。

1. **NIST SP 800-53 Rev. 5** をサブスクリプションに割り当てます。

1. 割り当てが表示されたら、NIST ビューを開きます。

1. 障害が発生している 2 つのコントロールを特定し、以下をキャプチャします。

    | フィールド | コントロール 1 | コントロール 2 |
    |-------|-----------|-----------|
    | コントロール ID とタイトル | | |
    | バッキング ポリシー名 | | |
    | クイック修正が利用可能 (Y/N) | | |

---

## CSPM シークレット スキャンの結果を調査する

1. **[クラウド セキュリティ態勢管理]** を開き、**[シークレット スキャン]** に移動します。

1. **sc500-lab4d-webapp** の結果を見つけます。

1. 結果の詳細を開き、以下を記録します。

    | フィールド | 値 |
    |-------|-------|
    | 結果の種類 | |
    | 影響を受けるリソース | sc500-lab4d-webapp |
    | 検出されたシークレット カテゴリ | |

1. **sc500-lab4d-webapp** 構成を開き、公開されているアプリ設定を特定します。

1. 2 番目のタブで **sc500-lab4d-kv** を開きます。

1. Key Vault シークレットがマネージド シークレット ベースラインとして存在することを確認します。

1. ノートに、以下をカバーする簡単な説明を記述します。

    - アプリ設定のシークレットにフラグが付けられた理由。
    - 適切に格納された Key Vault シークレットが同じ CSPM 結果の種類として扱われない理由。
    - この区別が修復所有権にとって重要な理由。

---

## 攻撃パス分析をレビューする

1. Defender for Cloud に戻り、**[攻撃パス分析]** を開きます。

1. 表示されている重大度が最も高いパスを開きます。

1. パス チェーンを順番に記録します。

    | Step | リソースまたはエッジ |
    |------|-------------------|
    | 初期の露出 | |
    | 侵入拡大 | |
    | 影響範囲のターゲット | |

1. Defender for Cloud で推奨される軽減策アクションを 1 つ記録します。

---

## ガバナンス所有権を割り当てる

1. **[推奨事項]** に戻ります。

1. オープンな推奨事項を選択します。

1. 以下の設定で**ガバナンス ルール**を割り当てます。

    - 所有者: **User3**
    - 期限: 今日から 14 日間
    - 通知頻度: 毎週

1. ガバナンスの割り当てを保存します。

1. 推奨事項の詳細に所有者と期限が表示されていることを確認します。

---

## オプション タスク: マルチクラウド コネクタのスコープをレビューする

1. **[環境設定]** を開き、**AWS** コネクタを選択します。

1. コネクタが存在する場合は、対象となるリソースの種類と調査結果の貢献をレビューします。

1. 環境にコネクタが存在しない場合は、この手順をノートに未構成としてマークします。

---

## まとめ

このラボでは、Defender for Cloud を使用して、生の調査結果から実用的な態勢ガバナンスに移行しました。

- セキュア スコアと推奨事項の影響を含むリスクを定量化しました。
- 態勢を名前付きコンプライアンス フレームワークにマップしました。
- 安全なシークレット管理パターンの外部でのシークレットの露出を調査しました。
- 攻撃パス コンテキストを使用して修復に優先順位を付けました。
- 説明責任のあるガバナンスの所有権とタイムラインを割り当てました。

これが、大規模なクラウド セキュリティ態勢管理の主要な運用パターンです。
