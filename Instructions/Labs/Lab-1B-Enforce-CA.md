# 条件付きアクセスを使用して MFA を強制する

最近実施された、あなたの組織の Entra ID テナントのセキュリティ レビューによれば、アクセス制御が全面的に Microsoft のセキュリティの既定値群のままであることが判明しました。この既定値群は画一的なベースラインであり、対象を指定したポリシーはありません。 一方で、AI プラットフォーム チームによって登録された新しいアプリケーションが機密性の高い API にアクセスしています。また、あるユーザー アカウントにサインイン リスクがあることが最近指摘されました。 あなたのタスクは、Azure portal にアクセスする、あるユーザーを対象として多要素認証 (MFA) を明示的に強制するように条件付きアクセス ポリシーを作成することと、そのポリシーを有効化する前に振る舞いを検証すること、および前述の新しい AI プラットフォーム アプリケーションを適切なスコープの API アクセス許可付きで登録することです。

条件付きアクセス ポリシーは、Microsoft Entra ID においてアクセス制御を ID シグナル、つまりユーザー、位置情報、デバイス、リスク レベルに基づいて適用するための主となるメカニズムです。 セキュリティの既定値群では、固定された一連の制御がすべてのユーザーに適用されますが、条件付きアクセス ポリシーはそれよりも細かく、誰を対象とするか、どの条件でポリシーをトリガーするか、どのアクセス制御を適用するかを制御できます。

このラボでは、次のことを行います。

- Azure portal にアクセスする特定ユーザーに MFA を要求するための条件付きアクセス ポリシーを作成する
- ポリシーを適用する前に、その振る舞いを What If シミュレーション ツールを使用して検証する
- ポリシーを有効にして、サインイン時に MFA が強制されることを確認する
- 新しいアプリケーションを Entra ID に登録し、スコープを限定した API アクセス許可を構成する

この演習の所要時間は約 **45** 分です。

---

## 条件付きアクセス ポリシーを作成する

条件付きアクセス ポリシーは 2 つの部分で構成されます。1 つは割り当て (ポリシーが誰と何に適用されるか)、もう 1 つはアクセス制御 (条件が満たされたときにどうするか) です。 ここでは、ある特定のユーザーを対象とするポリシーを作成し、そのユーザーが Azure portal にアクセスするときに MFA を要求します。

1. **Microsoft Entra 管理センター** (`https://entra.microsoft.com`) に、自分の *Administrator** 資格情報を使用してサインインします。

1. 左側のナビゲーションの **[Entra ID]** を展開して **[条件付きアクセス]** を選択します。

1. **[ポリシー]** をメニューから選択し、**[+ 新しいポリシー]** を選択します。

1. **[名前]** フィールドに「`sc500-require-mfa-portal`」と入力します。

1. **[割り当て]** で、**[0 人のユーザーまたはエージェントが選択済み]** を選択します。

1. 開いたページで **[ユーザーとグループの選択]** を選択してから、**[ユーザーとグループ]** チェックボックスをオンにします。

1. **[選択]** を選択し、**Adele Vance** を検索して選択してから、**[選択]** を選択して確定します。

    > **注**: ポリシーの対象を 1 人の特定ユーザーに限定すると、その振る舞いを検証するときに管理者や他のユーザーへの影響を防ぐことができます。 実務では、ポリシーの動作が期待どおりであることが確定したあとに対象範囲を拡大することになります。

1. **[割り当て]** の下の **[ターゲット リソース]** にある **[ターゲット リソースが選択されていません]** という項目を選択します。

1. **[ターゲット リソース]** ペインで、対象を **[すべてのリソース (以前の 'すべてのクラウド アプリ')]** に設定してから **[リソースの選択]** を選択します。

1. **[特定のリソースを選択する]** の下の **[なし]** リンクを選択します。

1. **[選択]** を選択し、**Office 365** を検索し、そのチェックボックスをオンにしてから **[選択]** を選択して確定します。

1. **[アクセス制御]** セクションを見つけます。

1. **[許可]** セクションの **[0 個のコントロールが選択されました]** という項目を選択します。

1. **[多要素認証を要求する]** を選択してから **[選択]** を選択します。

3. ポリシー ページの一番下にある **[ポリシーの有効化]** を **[レポート専用]** に設定します。

4. **[作成]** を選択してポリシーを保存します。

    **sc500-require-mfa-portal** が **[条件付きアクセス | ポリシー]** ページに表示されていて、その状態が**レポート専用**であることを確認します。

---

## レポート専用モードでポリシーを検証する

レポート専用モードでは、ポリシーが適用されるとどうなるかを、ユーザーをブロックしたり何かを要求したりすることなく記録することができます。 **What If** ツールでサインインをシミュレートできるので、ポリシーを有効にする前に、正しく適用できることを確認できます。 ここではこれを使用して、ポリシーの対象となっているユーザーとリソースが正しいことを確認します。

1. **[条件付きアクセス | ポリシー]** ページのツール バーで **[What If]** を選択します。

1. **[What If]** ペインで、次のとおりに構成します。

    | 設定 | Value |
    |---------|-------|
    | **ID の種類の選択 - ユーザー** | **[ユーザーの編集]** を使用して **Adele Vance** を選択する |
    | **対象の種類の選択 - クラウド アプリ** | Microsoft Forms |
    | **サインイン条件 - デバイス プラットフォーム** | Windows |
    | **サインイン条件 - クライアント アプリ | Browser |
    | その他すべての設定 | 既定値のままにする |

1. ページの一番下までスクロールします。

1. **[What If]** を選択してシミュレーションを実行します。 その後で**ページの一番下までスクロールします**。

1. **[適用されるポリシー]** の下で、**sc500-require-mfa-portal** が表示されていて **[許可コントロール]** が **[多要素認証を要求する]** であることを確認します。

    これで、ポリシーのスコープが正しく設定されていることが確定します。つまり、sc500-user02 が Azure portal にアクセスするときに MFA が強制されることになります。

    > **注**: このポリシーが結果に表示されない場合は、sc500-user02 がポリシー割り当てに**含まれるユーザー**のリストにあることと、**Microsoft Azure Management** が選択済みクラウド アプリであることを確認してください。 問題がある場合は、次に進む前に修正してください。

1. **[What If]** ペインを閉じます。

---

## ポリシーを有効にして MFA の強制を確認する

ポリシーが正しく構成されていることがシミュレーションで確認されました。 ここでポリシーを**オン**に切り替えて sc500-user02 としてサインインし、MFA を要求する画面が表示されることを確認します。

1. **[条件付きアクセス | ポリシー]** ページで、**sc500-require-mfa-portal** を選択して開きます。

1. **[ポリシーを有効にする]** を **[オン]** に設定します。

1. **[保存]** を選択します。

    ポリシー リストに表示される、このポリシーの状態は **[オン]** となっているはずです。

1. **InPrivate** または**プライベート**の新しいブラウザー ウィンドウを開きます。

1. Microsoft Forms (`https://forms.microsoft.com`) に移動します。

1. **[リソース]** タブに表示されている **Adele Vance** の認証情報を使用してサインインします。

1. パスワードを入力した後に、MFA を要求する画面が表示されることを確認します。 これで、条件付きアクセス ポリシーがアクティブでありステップアップ認証がこのユーザーに対して強制されていることが確認されます。

    > **注**: MFA を要求する画面が表示されない場合は、ポリシーの状態が **[オン]** である (レポート専用ではない) ことと、含まれるユーザーのリストに sc500-user02 があること、および除外が適用されていないことを確認してください。

1. MFA チャレンジを、sc500-user02 に対して登録済みの方法で完了します。 TOTP コードまたは Authenticator の詳細は **[リソース]** タブにあります。

1. Azure portal にサインインできたことを確認します。 条件付きアクセス ポリシーに従ってステップアップ認証が要求され、アクセス権は MFA チャレンジの完了後に付与されました。

1. InPrivate のブラウザー ウィンドウを閉じます。

## アプリケーションを Entra ID に登録する

AI プラットフォーム チームは、Entra ID に登録されたアプリケーション ID を必要としています。このチームのアプリケーションがユーザーの代理で認証と API の呼び出しを実行できるようにするためです。 アプリを登録するとクライアント ID が発行されることに加えて、そのアプリケーションにどのアクセス許可が必要かを定義する場所が用意されます。 ここでは、そのアプリケーションを登録し、最小限の特権の原則に従ってスコープを限定した、委任されたアクセス許可を追加します。

1. **グローバル管理者**のブラウザー ウィンドウ ([Microsoft Entra 管理センター](https://entra.microsoft.com)) に戻ります。

1. 左側のナビゲーションの **[アプリケーション]** を展開して **[アプリの登録]** を選択します。

1. **[+ 新規登録]** を選択します。

1. **[アプリケーションの登録]** ページで、次のとおりに構成します。

    | 設定 | 値 |
    |---------|-------|
    | 名前 | **`sc500-ai-platform-app`** |
    | サポートされているアカウントの種類 | **シングル テナントのみ - Contoso** |
    | リダイレクト URI | 空白のままにします |

1. **登録** を選択します。

    Entra ID での登録が作成されて、**sc500-ai-platform-app** の **[概要]** ページが開きます。

1. **[概要]** ページで、**[アプリケーション (クライアント) ID]** フィールドを見つけて値をコピーします。 この値は、このアプリケーションにアクセスを許可するときに使用します。

    > **注**: アプリケーション (クライアント) ID は、Entra ID でのこの登録の一意の識別子です。 これはアプリケーションが OAuth フローの中で Entra ID に対して認証するときに、クライアント シークレットまたは証明書とともに使用されます。

1. アプリ登録画面の左側メニューで、**[API のアクセス許可]** を選択します。

1. **[+ アクセス許可の追加]** を選択します。

1. **[API アクセス許可の要求]** ペインで **[Microsoft Graph]** を選択します。

1. **[委任されたアクセス許可]** を選択します。

1. 検索ボックスで、**`User.Read`** を検索します。

1. **[ユーザー]** を展開し、**[User.ReadBasic.All]** を選択してから **[アクセス許可の追加]** を選択します。

    > **注**: **User.Read** は委任されたアクセス許可の 1 つであり、これでアプリケーションはサインイン済みユーザーの代理でそのユーザーの基本的プロフィールを読み取ることができます。 このアクセス許可は、誰がサインインしているかをアプリケーションで特定する必要がある場合に最小限必要となるものです。 委任されたアクセス許可は、サインイン済みユーザーのコンテキスト内で作用するものであり、標準的なテナント設定の下では User.Read に対して管理者の同意は必要ありません。

1. **[API のアクセス許可]** ページで、**User.ReadBasic.All** が **[構成されたアクセス許可]** の下に表示されていて種類が **[委任済み]** であることを確認します。

    > **注**: **[管理者の同意を与えます]** ボタンが表示され、状態が **[付与されていません]** と表示されている場合は、そのテナントではすべてのアクセス許可に対して管理者の同意が必要です。 **[<あなたのテナント> に管理者の同意を与えます]** を選択して、確定します。 講師から、このテナント全体に適用される設定について説明があります (該当する場合)。

1. **[概要]** ページに戻り、**[アプリケーション (クライアント) ID]** が記録されていることを確認します。

## まとめ

このラボでは、セキュリティ既定値群ベースラインの代わりとなる明示的な条件付きアクセス ポリシーを作成し、Azure portal にアクセスする特定のユーザーに対して MFA を強制するように設定しました。 このポリシーをレポート専用モードで What If シミュレーション ツールを使用して検証してから、強制を有効にして、MFA を要求する画面がサインイン時に表示されることを確認し、MFA チャレンジを完了してアクセスが許可されることを確認しました。 その後に、AI プラットフォーム アプリケーションを Entra ID に登録し、スコープを限定した委任された API アクセス許可を最小限の特権の原則を使用して構成しました。

この演習は無事に完了しました。
