# ラボのセットアップ

管理を承認されている Azure サブスクリプションと Microsoft Entra テナントを使用します。 このラボでは、**セキュリティ管理者**と**グローバル管理者**の役割、セキュリティ コンピューティング ユニット (SCU)、Microsoft Security Copilot ライセンスが必要です。 演習期間中のみ特権ロールを使用し、組織の最小限の特権の実践に従います。

===

# Microsoft Security Copilot を構成して使用する

あなたは、運用セキュリティ環境で運用するために Security Copilot を準備しています。 目的は、プロンプトを実行するだけでなく、容量、アクセス許可、データ アクセス、プラグイン スコープを設定して、Copilot が、必要のない範囲まで影響を及ぼすことなく、典拠付きの有用な応答を提供できるようにすることです。

このラボでは、次のことを行います。

- Security Copilot の SCU 容量をプロビジョニングします。
- ワークスペースのデータ共有の設定を構成します。
- 委任されたアナリスト ユーザーに共同作成者のアクセス権を割り当てます。
- Microsoft のコア セキュリティ プラグインを有効にします。
- 組み込みの Copilot エージェントを確認して有効にします。
- 接続されたセキュリティ データに対して構造化されたプロンプトを実行します。

この演習の所要時間は約 **45** 分です。

> **注意**: このラボでは、お使いの環境で Security Copilot SCU のプロビジョニングが有効になっていること、および関連する Microsoft セキュリティ データ ソースが使用可能であることが想定されています。

---

## 構成済みの状態を確認する

1. Azure portal にサインインして **[リソース グループ]** を開きます。

1. **sc500-lab4f-rg** を選び、**sc500-lab4f-storage** が存在することを確認します。

1. お使いのテナント アカウントに、Security Copilot で SCU 容量をプロビジョニングするために必要なアクセス権が含まれることを確認します。

---

## Security Copilot の容量をプロビジョニングする

1. **User1** アカウントを使用して [https://securitycopilot.microsoft.com](https://securitycopilot.microsoft.com) にサインインします。

1. 容量プロビジョニングのセットアップ フローを始めます。

1. ラボ環境で別のリージョンの使用が指示されていない限り、**米国東部** で **1 SCU** をプロビジョニングします。

1. プロビジョニングが完了し、ワークスペースが使用可能になったことを確認します。

1. 容量の設定をメモに記録しておきます。

    | フィールド | 値 |
    |-------|-------|
    | リージョン | 米国東部 (ラボ環境で特に指示されている場合を除く) |
    | SCU 数 | 1 |

---

## ワークスペースとロールの割り当てを構成する

1. Security Copilot で **[所有者の設定]** を開きます。

1. **[データ共有]** を開き、このラボ環境用に最小特権の共有の選択を構成します。

1. 設定を保存します。

1. **[ロール]** を開きます。

1. ご自分のアカウントがワークスペース所有者として一覧に表示されていることを確認します。

1. **Security Copilot 共同作成者**ロールを **User3** に割り当てます。

1. ロールの割り当てが表示されていることを確認します。

---

## セキュリティ プラグインを有効にする

1. Security Copilot で **[ソース]** または **[プラグイン]** を開きます。

1. 次のプラグインを有効にします。

    - Microsoft Defender XDR
    - Microsoft Defender for Cloud
    - Microsoft Sentinel
    - Microsoft Entra

1. プラグインの接続状態が更新されるまで待ちます。

1. 各プラグインが接続済みと示されていることを確認します。

1. プラグインの状態をメモに記録しておきます。

    | プラグイン | 状態 |
    |--------|--------|
    | Defender XDR | |
    | Defender for Cloud | |
    | Sentinel | |
    | Entra | |

---

## 組み込みエージェントを確認して有効にする

1. Security Copilot で **[エージェント]** を開きます。

1. **[脆弱性の影響の評価]** (または、環境内にある同等の組み込み脆弱性関連エージェント) を選びます。

1. エージェントの詳細を確認します。

    - パーパス
    - 必要なデータ ソース
    - アクセス許可のスコープへの影響

1. エージェントを有効にします。

1. このエージェントの潜在的な影響範囲がプラグインのアクセス スコープにどのように依存するかを、2 - 3 行でメモにまとめておきます。

---

## 典拠付きのセキュリティ プロンプトを実行する

1. Security Copilot のメイン プロンプト エクスペリエンスに戻ります。

1. 次のプロンプトを実行します。

    ```input
    Summarize the current security posture of this environment based on Defender for Cloud findings. What are the top 3 recommendations?
    ```

1. 応答と引用を確認します。

1. 次のフォローアップ プロンプトを実行します。

    ```input
    Provide step-by-step remediation actions for the top recommendation you just identified.
    ```

1. メモに記録しておきます。

    | フィールド | 値 |
    |-------|-------|
    | 返された上位の推奨事項 | |
    | 参照されているソース/プラグイン | |
    | 修復手順の実行可能性 | |

---

## まとめ

このラボでは、運用セキュリティ プラットフォーム コンポーネントとして Security Copilot を構成しました。

- コンピューティング容量をプロビジョニングしました。
- ワークスペース ガバナンスを適用し、ロールのアクセスを委任しました。
- プラグインを介してコア Microsoft セキュリティ データ ソースを接続しました。
- 組み込みの自律セキュリティ エージェントを有効にしました。
- Defender の態勢データに関連付けられた、典拠付きのプロンプトを実行しました。

これにより、4 日目のキャップストーン パターンが確立されます。セキュリティ スタックの構成品質によって、Copilot の出力品質が直接向上します。
