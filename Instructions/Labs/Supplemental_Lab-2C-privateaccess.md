# Microsoft Entra Private Access を構成する (追加ラボ)

> **注**: これはラボ 2C の追加ラボです。 ラボ 2C のハブスポーク ネットワークとワークロード VM (`sc500-lab2c-vm`) が設定されている必要があります。開始前、ラボ 2C 環境をそのまま維持してください。 このラボの一部として、グローバル セキュア アクセス コネクタを作成して登録します。 始める前に、[Microsoft Entra 管理センター](https://entra.microsoft.com)を開き、左側メニューの **[グローバル セキュア アクセス]** を展開して、そのセクションにアクセスできることを確認します。これにより、グローバル セキュア アクセスがテナントでライセンスされ有効化されていることが確認されます。

リモートで作業している開発者が、`sc500-lab2c-vm` 上で動作している AI 推論サービスのエンドポイントにアクセスする必要があります。しかし、しかし、その VM は現在、Azure Firewall の背後にあるプライベート サブネット内にあり、パブリックな受信アクセスはありません。 従来のソリューション (VPN、ジャンプ ホスト、パブリック IP) は、攻撃面を広げてしまうか、チームが持っていないインフラストラクチャを必要とします。 

**Microsoft Entra Private Access** は、VPN を必要とせずにプライベート リソースへのゼロトラスト ネットワーク アクセス (ZTNA) を提供します。 プライベート ネットワーク内にインストールされた軽量なコネクタを使用して、認証された Entra ID ユーザーからのトラフィックを中継します。そのため、アクセスはネットワーク境界メンバーシップではなく、ID、条件付きアクセス ポリシー、セッション制御によって管理されます。

このラボでは、次のことを行います。

- スポーク仮想ネットワーク内に専用のコネクタ サブネットを作成する
- グローバル セキュア アクセス コネクタ VM をデプロイし、コネクタ エージェントをインストールする
- コネクタが登録済みかつアクティブであることを確認する
- ワークロード VM のプライベート IP をターゲットにしたクイック アクセスのプライベート リソースを構成する
- クイック アクセス アプリケーションをユーザーに割り当てる
- グローバル セキュア アクセスの構成とログを確認する

この演習の所要時間は約 **30** 分です。

---

## コネクタ サブネットを作成する

グローバル セキュア アクセス コネクタは、保護する対象のリソースに到達できるように、プライベート ネットワーク内の VM 上で実行されている必要があります。 スポーク仮想ネットワーク内に専用のサブネットを作成します。これは `workload-subnet` とは別で、コネクタ VM がワークロードに適用されている NSG やルート テーブルと同じルールの対象にならないようにするためです。

1. [Azure portal](https://portal.azure.com) で、**[仮想ネットワーク]** を検索して選択します。

1. **[sc500-lab2c-spoke-vnet]** を選択します。

1. 左メニューの **[設定]** で、**[サブネット]** を選択します。

1. **[+ サブネット]** を選択します。

1. サブネットを構成します。

    | 設定 | 値 |
    |---------|-------|
    | **サブネットの目的** | 既定値 |
    | **名前** | connector-subnet |
    | **開始アドレス** | 10.4.1.0 |
    | **[サイズ]** | /24 (256 アドレス) |
    | **ネットワーク セキュリティ グループ** | なし |
    | **ルート テーブル** | なし |
    | **プライベート サブネットを有効にする** | Unchecked |
    | **NAT Gateway** | なし |
    | **サービス エンドポイント** | なし |
    | **サブネットの委任** | なし |
    | **プライベート エンドポイントのネットワーク ポリシー** | 無効 |

1. **[追加]** を選択します。

    > **注**: connector-subnet は意図的にルート テーブルなしとしています。 `workload-subnet` は、すべての送信トラフィックを強制的に Azure Firewall 経由にするルート テーブルを使用しており、GSA コネクタの登録エンドポイント向けに追加のファイアウォール アプリケーション ルールが必要になります。 既定の Azure ルーティングを用いる別のサブネットを使用することで、コネクタ VM から Microsoft のグローバル セキュア アクセス インフラストラクチャへの直接の送信 HTTPS アクセスができます。これは、コネクタが必要とする送信専用のパターンです。

## コネクタ VM をデプロイする

1. Azure portal で、**[仮想マシン]** を検索して選択します。

1. **[+ 作成]** → **[Azure 仮想マシン]** を選択します。

1. **[基本]** タブで次のように構成します。

    | 設定 | 値 |
    |---------|-------|
    | **リソース グループ** | sc500-lab2c-rg |
    | **仮想マシン名** | sc500-lab2c-gsa-connector-vm |
    | **リージョン** | `sc500-lab2c-rg` と同じ Azure リージョン (米国東部。ラボ環境で特に指示されている場合を除く) |
    | **イメージ** | Windows Server 2022 Datacenter: Azure Edition |
    | **[サイズ]** | Standard_B2s |
    | **管理者ユーザー名** | sc500vmadmin |
    | **管理者パスワード** | SC500-Lab2C-2026! |
    | **パブリック インバウンド ポート** | 選択したポートを許可する |
    | **受信ポートの選択** | RDP (3389) |

1. **[次へ: ディスク]** を選択し、既定値をそのまま使用して、**[次へ: ネットワーク]** を選択します。

1. **[ネットワーク]** タブで次のように構成します。

    | 設定 | 値 |
    |---------|-------|
    | **仮想ネットワーク** | sc500-lab2c-spoke-vnet |
    | **サブネット** | connector-subnet (10.4.1.0/24) |
    | **パブリック IP** | (新規) — 既定の名前のまま |
    | **NIC ネットワーク セキュリティ グループ** | Basic |
    | **パブリック インバウンド ポート** | 選択されたポートを許可 — RDP(3389) |

1. 残りの既定値をそのまま使用し、**[確認および作成]** を選択して、**[作成]** を選択します。

    > **注**: パブリック IP と RDP アクセスは、VM に接続してコネクタ エージェントをインストールするためにのみ必要です。 コネクタが登録されると、Microsoft の GSA インフラストラクチャへの送信専用トンネルが確立されます。進行中の操作に受信アクセスは必要ありません。 運用環境では、パブリック IP の代わりに Azure Bastion や既存のジャンプ ホストを使用します。

1. デプロイが完了するのを待ってから続行します。

## コネクタ エージェントをインストールして登録する

1. [Microsoft Entra 管理センター](https://entra.microsoft.com)で **[グローバル セキュア アクセス]** を展開し、**[接続]** を選択します。

1. **[コネクタとセンサー]** を選択します。

1. **[コネクタ サービスのダウンロード]** を選択します。

1. 使用条件ページで使用条件を確認し、**[規約に同意してダウンロード]** を選択します。

    これにより **MicrosoftEntraPrivateNetworkConnectorInstaller.exe** インストーラー ファイルがダウンロードされます。

1. Azure ポータルで **[仮想マシン]** → **[sc500-lab2c-gsa-connector-vm]** → **[概要]** に移動し、**[パブリック IP アドレス]** を確認します。

1. **[リモート デスクトップ接続]** を開き、以下を使用してパブリック IP アドレスに接続します。
    - **ユーザー名**: sc500vmadmin
    - **パスワード**: SC500-Lab2C-2026!

1. RDP セッション内で **[サーバー マネージャー]** を開きます (ログイン時に自動的に起動するか、スタート メニューで検索)。

1. 左側のペインで、**[ローカル サーバー]** を選択します。

1. **[IE セキュリティ強化の構成]** を探します。これは **[オン]** と表示されています。 その隣の **[オン]** を選択します。

1. ダイアログで **[管理者]** と **[ユーザー]** の両方を **[オフ]** に設定し、**[OK]** を選択します。

    > **注**: Windows Server では [IE セキュリティ強化の構成] が既定で有効になっており、コネクタ インストーラーが起動するブラウザーベースのサインイン ポップアップがブロックされます。 これをオフにすることで、認証フローを完了できるようになります。 この設定は、この VM にのみ影響します。

1. コネクタ インストーラーをコピーして実行します。

1. プロンプトが表示されたら、コネクタをテナントに登録するために、**User1** (グローバル管理者) の資格情報でサインインします。

    インストーラーはコネクタを登録し、**Microsoft Entra プライベート ネットワーク コネクタ** Windows サービスを自動的に起動します。

1. RDP セッションを閉じます。

## コネクタがアクティブであることを確認する

1. Entra 管理センターで **[グローバル セキュア アクセス]** → **[接続]** → **[コネクタとセンサー]** に移動します。

    **sc500-lab2c-gsa-connector-vm** が一覧に表示され、状態が **[アクティブ]** になっていることを確認します。

    > **注**: エージェントのインストール後、状態が [アクティブ] に更新されるまで最大 5 分ほどかかります。 [非アクティブ] のままの場合は、VM に再度サインインし、**Microsoft Entra プライベート ネットワーク コネクタ** Windows サービスが **[実行中]** 状態になっていることを確認します。

1. **sc500-lab2c-gsa-connector-vm** が属している**コネクタ グループ**をメモします。次のタスクでクイック アクセスを構成する際にこれを参照します。

## ワークロード VM 用のクイック アクセスを構成する

**クイック アクセス**は、単一のプライベート リソースまたは範囲に対して Entra Private Access を構成する最短の方法です。 Entra ID 内にプライベート リソースを表すエンタープライズ アプリケーションを作成し、登録済みコネクタ経由で特定の IP アドレスとポート範囲へのトラフィックをマッピングします。

ワークロード VM (`sc500-lab2c-vm`) の TCP ポート 443 (推論サービスで使用される HTTPS ポート) へのアクセスを提供するようにクイック アクセスを構成します。

1. Entra 管理センターの **[グローバル セキュア アクセス]** で **[アプリケーション]** を選択します。

1. **[クイック アクセス]** を検索します。

1. **[クイック アクセス]** ページで、次のように構成します。

    | 設定 | 値 |
    |---------|-------|
    | **名前** | sc500-inference-access |
    | **コネクタ グループ** | 既定値 (または sc500-lab2c-gsa-connector を含むグループ) |

1. **[クイック アクセス アプリケーション セグメント]** の **[+ クイック アクセス アプリケーション セグメントの追加]** を選択します。

1. セグメントを構成します。

    | 設定 | Value |
    |---------|-------|
    | **送信先の種類** | IP アドレス (IP address) |
    | **IP アドレス (IP address)** | sc500-lab2c-vm のプライベート IP アドレス ([仮想マシン] → [sc500-lab2c-vm] → [概要] → [プライベート IP アドレス] で確認) |
    | **ポート** | 443 |
    | **プロトコル** | TCP |

1. **[適用]** を選択し、**[保存]** を選択します。

    > **注**: クイック アクセスは、Entra ID 内に `sc500-inference-access` という名前のエンタープライズ アプリケーションを作成します。 このアプリケーションは **[Entra ID] → [エンタープライズ アプリケーション]** に表示され、条件付きアクセス ポリシーのターゲットにすることができます。これにより、ネットワークレベルの変更を行うことなく、プライベート リソースへのすべてのアクセスに対して MFA、デバイス コンプライアンス、サインイン リスク制御を適用できます。

## クイック アクセス アプリケーションをユーザーに割り当てる

他のエンタープライズ アプリケーションと同様に、クイック アクセス アプリケーションは、アクセスを必要とするユーザーまたはグループに割り当てる必要があります。 割り当てがない場合、ユーザーはグローバル セキュア アクセス経由でプライベート リソースにアクセスできません。

1. Entra 管理センターで **[ID]** → **[アプリケーション]** → **[エンタープライズ アプリケーション]** に移動します。

1. **sc500-inference-access** を検索して選択します。

1. 左側のメニューの **[管理]** の下にある **[ユーザーとグループ]** を選択します。

1. **[+ ユーザーまたはグループの追加]** を選択します。

1. **[ユーザー]** で **[選択なし]** を選択します。

1. 「**User3**」を検索して選択し、**[選択]** を選択します。

1. **[ロールの選択]** では、ロールが **[ユーザー]** に事前設定されています。これは正しい設定です。

1. **割り当て**を選びます。

    > **注**: これで、**User3** は、`sc500-inference-access` クイック アクセス アプリケーションへの割り当てを持つようになりました。 このユーザーが、**グローバル セキュア アクセス クライアント**を実行しているデバイスにサインインすると、ポート 443 のワークロード VM のプライベート IP 宛てのトラフィックは、VPN 構成やネットワーク ファイアウォールのルール変更なしに、自動的にコネクタ経由でトンネリングされます。

---

## クイック アクセスの構成を確認する

1. **[グローバル セキュア アクセス]** → **[アプリケーション]** → **[クイック アクセス]** に戻ります。

1. `sc500-inference-access` アプリケーションで、構成したセグメントが表示されていることを確認します。
    - 宛先: ワークロード VM のプライベート IP
    - ポート:443
    - プロトコル:TCP

1. Entra 管理センターで **[グローバル セキュア アクセス]** → **[監視]** → **[トラフィック ログ]** に移動します。

    > **注**: 運用環境のシナリオでは、エンドユーザー デバイスに**グローバル セキュア アクセス クライアント**をインストールし、**User3** としてサインインして、コネクタを経由するトラフィックを生成します。 トラフィック ログには、すべてのトンネル セッションが記録され、どのユーザーが、いつ、どのデバイスから、どのプライベート リソースへアクセスしたかが表示されます。 このログは、ゼロトラスト アーキテクチャにおいてネットワーク境界ログに代わる、ID によって制御される監査証跡です。

    > **ラボの制約**: この追加ラボでは、ラボ用 VM 上にグローバル セキュア アクセス クライアントをインストールしてテストすることは範囲外です。 ここで完了した構成 (コネクタ登録、クイック アクセス アプリケーション セグメント、ユーザー割り当て) が、完全な管理者のプロビジョニング ワークフローです。 運用環境へのデプロイでは、エンドユーザーが `aka.ms/GlobalSecureAccessClient` から軽量クライアントをインストールし、サインイン時にプライベート アクセスが透過的に機能し始めます。

## まとめ

この追加ラボでは、**Microsoft Entra Private Access** を構成し、AI 推論ワークロードの VM に対して、パブリック インターネットに公開したり VPN を必要としたりすることなく、ID によって制御されたアクセスを提供しました。

`sc500-lab2c-gsa-connector-vm` にインストールした**グローバル セキュア アクセス コネクタ**は、Entra の ID プレーンとプライベート ネットワークの間のブリッジとして機能します。 ワークロード VM のプライベート IP のポート 443 をターゲットとする**クイック アクセス アプリケーション セグメント**を作成し、承認されたユーザーがコネクタ トンネルを通じてリソースにアクセスできるようにしました。

エンタープライズ アプリケーションを **User3** に割り当てて、アクセスがネットワーク メンバーシップではなく Entra ID の ID によって管理されることを明確にしました。 同じユーザーをこのアプリケーションに適用される**条件付きアクセス ポリシー**の対象にすると、プライベート アクセスが許可される前に、MFA、準拠デバイスの状態、またはサインイン リスクのしきい値が必要になる場合があります。 これがゼロトラスト ネットワーク アクセス モデルであり、VPN トンネルの代わりに、ID とデバイスの健全性がアクセス制御の境界となります。
