# SC-500 ラボ 3D - セットアップ手順

## 概要

このフォルダーには、「**ラボ 3D: Defender for Cloud を使用して AI セキュリティを監視する**」のセットアップ用リソースが含まれています。

⚠️**重要なタイミング要件**: このラボは、セットアップとラボ実施の間に **24 時間以上**のリード タイムが必要です。 受講者が検出結果を確認できるように、敵対的トラフィックを実行し、それが Defender for AI によって処理されている必要があります。

## このフォルダー内のファイル

- **lab-3d-setup.json** - Azure portal の [カスタム テンプレートのデプロイ] からラボのインフラストラクチャをデプロイするための ARM テンプレート
- **generate-adversarial-traffic.ps1** - Defender の検出結果を生成するために、敵対的なクエリ (ジェイルブレイク、プロンプト インジェクション、大量バースト) を送信する PowerShell スクリプト
- **README.md** - このファイル

## セットアップによってデプロイされるもの

`lab-3d-setup.json` ARM テンプレートでは、**sc500-lab3d-rg** リソース グループに以下のリソースがプロビジョニングされます。

### コア インフラストラクチャ
- **Azure OpenAI Service** (`sc500-lab3d-ai-{instanceId}`)
  - 20 TPM 容量の gpt-5.4-mini モデル デプロイ (GlobalStandard SKU)
  - **カスタム コンテンツ フィルターは意図的になし** (既定値または [なし] を使用)
  
- **Azure AI Foundry ハブ** (`sc500-lab3d-hub-{instanceId}`)
  - Foundry プロジェクトのハブ ワークスペース
  
- **Azure AI Foundry プロジェクト** (`sc500-lab3d-foundry`)
  - AI Foundry ポータルから参照できるプロジェクト ワークスペース
  - **コンテンツ セーフティ ガードレールなし** (意図的 - 敵対的なトラフィックがモデルに到達できるようにする)

### サポート リソース
- **Log Analytics ワークスペース** (`sc500-lab3d-logs`)
- **Application Insights** (`sc500-lab3d-insights`)
- **ストレージ アカウント** (`sc500lab3d{instanceId}`) - AI ハブ/プロジェクト用
- **Key Vault** (`sc500-3d-kv-{instanceId}`) - AI ハブ/プロジェクト用

## ラボの目的 (ラボ 3C との違い)

| ラボ | パーパス | セキュリティの状態 | 受講者の活動 |
|-----|---------|---------------|------------------|
| **ラボ 3C** | セキュリティ コントロールを構成する | 最初は非保護状態で開始し、受講者が堅牢化する | レート制限、認証、コンテンツ フィルターを適用 |
| **ラボ 3D** | セキュリティの検出結果を監視する | 意図的に非保護のまま | あらかじめ実行された攻撃による Defender のアラートを確認 |

ラボ 3D は**監視と検出のラボ**であり、構成作業のラボではありません。 受講者は、意図的に保護されていないエンドポイントに対して事前に実行された敵対的トラフィックから生成された検出結果を確認します。

## 展開指示

### オプション 1: Azure portal を使ってデプロイする (推奨)

1. [Azure portal](https://portal.azure.com) にサインインする
2. **[カスタム テンプレートのデプロイ]** を検索します
3. **[エディターで独自のテンプレートを作成する]** を選択します
4. **[ファイルの読み込み]** をクリックして `lab-3d-setup.json` をアップロードします
5. **[保存]** をクリックします
6. パラメーターを構成します。
   - **サブスクリプション**: ラボのサブスクリプションを選択します
   - **場所**: Azure OpenAI がサポートされている Azure リージョンを選択します (例: 米国東部、西ヨーロッパ)
   - **ラボ インスタンス ID**: **空欄のままにして**、サブスクリプション ID から 8 文字のハッシュを自動生成します。 特定のオーバーライドが必要な場合のみ、値を入力します。
   - **AI 用 Defender を有効にする**: `true` のままにします (サブスクリプションで AI サービス用 Defender が有効になる)
7. **[確認および作成]**、**[作成]** の順にクリックします

**デプロイ時間:** 約 10 - 15 分

### オプション 2: Azure CLI を使ってデプロイする

```bash
# Set variables
LOCATION="eastus"

# Deploy the template (labInstanceId defaults to a hash of the subscription ID)
az deployment sub create \
  --location $LOCATION \
  --template-file lab-3d-setup.json \
  --parameters location=$LOCATION
```

### オプション 3: PowerShell を使ってデプロイする

```powershell
# Set variables
$Location = "eastus"

# Deploy the template (labInstanceId defaults to a hash of the subscription ID)
New-AzSubscriptionDeployment `
  -Location $Location `
  -TemplateFile .\lab-3d-setup.json `
  -location $Location
```

## デプロイ後の構成 (重要)

### ステップ 1: AI サービス用 Defender を有効にする

1. Azure portal で **Microsoft Defender for Cloud** に移動します
2. 左側のメニューから **[環境設定]** を選択します
3. サブスクリプションを選択します。
4. **[Defender プラン]** ページで、**[AI サービス]** (または **[AI 用 Defender]**) を見つけます
5. **[オン]** に設定します
6. **[保存]** をクリックします

**注:** ARM テンプレート パラメーター `enableDefenderForAI` は `true` に設定されていますが、サブスクリプションレベルでの Defender の有効化には手動による確認が必要な場合があります。

### ステップ 2: コンテンツ フィルターが割り当てられていないことを確認する

これは非常に重要です。コンテンツ フィルターがあると、敵対的クエリはモデルに到達する前にブロックされ、Defender が攻撃パターンを検出できなくなります。

1. [Azure AI Foundry ポータル](https://ai.azure.com)に移動します
2. **sc500-lab3d-foundry** プロジェクトを選択します
3. 左側のナビゲーションで **[安全性 + セキュリティ]** > **[コンテンツ フィルター]** を選択します
4. **gpt-5.4-mini** のデプロイが次のように表示されていることを確認します。
   - コンテンツ フィルター: **[既定値]** または **[なし]** (中程度または高いしきい値を持つカスタム フィルターではないこと)
   - カスタム フィルターが割り当てられている場合は、削除するか、[なし] に設定します

**この重要性について:** カスタムのコンテンツ セーフティ フィルターが有効であると、モデルが処理する前にジェイルブレイクやプロンプト インジェクションの試行がブロックされます。 AI 用 Defender は、ブロックされた要求ではなく、モデルとの対話の中の攻撃 "パターン" を検出します。** 対話がなければ検出もなく、得られる検出結果もありません。

### ステップ 3: エンドポイント URL と API キーを取得する

これらの値は敵対的トラフィックのスクリプトを実行するために必要です。

1. **[リソース グループ]** > **[sc500-lab3d-rg]** > **[sc500-lab3d-ai-{instanceId}]** に移動します
2. 左側のメニューから **[キーとエンドポイント]** を選択します
3. コピー:
   - **エンドポイント:** `https://sc500-lab3d-ai-{instanceId}.openai.azure.com/`
   - **キー 1**: API キー値

4. エンドポイントの完全な URL を作成します。
   ```
   https://sc500-lab3d-ai-{instanceId}.openai.azure.com/openai/deployments/gpt-5.4-mini/chat/completions?api-version=2024-02-01
   ```

または、デプロイの出力を確認します。
```bash
az deployment sub show --name sc500-lab3d-infrastructure --query properties.outputs
```

### ステップ 4: 敵対的トラフィックのスクリプトを実行する

このスクリプトは、モデルのエンドポイントに対して 15 件の敵対的クエリを送信します (ジェイルブレイク 5 件、プロンプト インジェクション 5 件、大量バースト 5 件)

1. Open PowerShell 7 以上 (または Windows PowerShell 5.1)
2. `Allfiles\Lab-3D` フォルダーに移動します
3. 次のスクリプトを実行します。

   ```powershell
   .\generate-adversarial-traffic.ps1 `
       -EndpointUrl "https://sc500-lab3d-ai-{instanceId}.openai.azure.com/openai/deployments/gpt-5.4-mini/chat/completions?api-version=2024-02-01" `
       -ApiKey "YOUR_API_KEY_HERE"
   ```

4. 出力を確認します。
   - **緑色のメッセージ** (`HTTP 200`) = クエリが正常に送信され、モデルが応答した
   - **黄色のメッセージ** (`HTTP 4xx/5xx`) = 一部の敵対的クエリに関する想定内のもの
   - **赤色のメッセージ** (`HTTP 400/403 blocked by content filter`) = **問題** - コンテンツ フィルターがアクティブです。削除してから、もう一度実行してください

5. 15 件のクエリすべてが完了していることを確認します (スクリプトは 12 - 15 秒かかります)

### ステップ 5: 24 時間以上待つ ⏰

**これは最も重要な手順です。**

AI 用 Defender には以下のための時間が必要です。
1. クエリからの動作テレメトリを収集
2. 複数の要求にまたがるパターンを分析
3. シグナルをセキュリティの検出結果に関連付ける
4. Defender for Cloud ダッシュボードに検出結果を表示

**最短待ち時間:** 24 時間  
**推奨待ち時間:** 一貫した結果のために 36 - 48 時間

### ステップ 6: ラボ実施前に検出結果を確認する

環境を受講者向けに準備完了とマークする前に、次の操作と確認を行います。

1. Azure portal で **Microsoft Defender for Cloud** に移動します
2. 左側のメニューで、**[データと AI セキュリティ]** を選択します
3. 確認:
   - **sc500-lab3d-foundry** が、保護されたリソースの一覧に表示されます
   - 状態は **[保護済み]** になっています
   - **少なくとも 2 件のセキュリティ検出結果**が検出結果/アラート セクションで確認できます

4. 検出結果が 2 件未満しか表示されない場合:
   - さらに 6 - 12 時間待機
   - `generate-adversarial-traffic.ps1` を再実行 (シグナルをさらに追加)
   - さらに 12 - 24 時間待って再確認

## 受講者が見るもの

ラボ中、受講者は以下のことを行います。

1. **保護の状態を確認する** - `sc500-lab3d-foundry` が保護された AI リソースとして表示されていることを確認します
2. **アクティブな検出結果を確認する** - 事前に実行された敵対的トラフィックから生成された 1 - 3 件の検出結果を確認します。
   - ジェイルブレイク試行のパターン
   - プロンプト インジェクションのプローブ
   - 異常な大量バースト
3. **重大度と推奨対処を確認する** - Defender で何が検出され、どのような対処が推奨されているかを理解します
4. **AI セキュリティに関する推奨事項を確認する** - コンテンツ フィルターの適用、監視の有効化などに関する推奨事項を確認します

受講者はこのラボで何かを構成したり修正したりすることはせず、検出結果の観察と解釈だけを行います。

## トラブルシューティング

### 問題: 24 時間を過ぎても検出結果が表示されない
**考えられる原因**:
- コンテンツ フィルターによって、クエリがモデルに到達する前にブロックされている → コンテンツ フィルターを削除し、スクリプトを再実行します
- AI サービス用 Defender が有効になっていない → [Defender for Cloud] > [環境設定] で確認します
- 敵対的トラフィックのスクリプトが失敗している → スクリプト出力で HTTP 400/403 エラーを確認します

**解決方法:**
1. gpt-5.4-mini にコンテンツ フィルターが割り当てられていないことを確認します
2. `generate-adversarial-traffic.ps1` を再実行します
3. さらに 24 時間待ちます
4. それでも検出結果が表示されない場合は、[Defender for Cloud] > [ワークロード保護] > [AI サービスのカバレッジ] を確認します

### 問題: スクリプトで "HTTP 403 コンテンツ フィルターによるブロック" が返される
**解決策:** コンテンツ フィルターがアクティブです。 ai.azure.com > sc500-lab3d-foundry > [安全性 + セキュリティ] > [コンテンツ フィルター] にアクセスし、gpt-5.4-mini に割り当てられているカスタム フィルターを削除してください。 [なし] または [既定値] (すべてのしきい値がオフ) に設定します。

### 問題: AI サービス用 Defender に "有効化されていません" と表示される
**解決策:** [Defender for Cloud] > [環境設定] > [ご利用のサブスクリプション] > [Defender プラン] > [AI サービス] → [オン] に設定 → [保存] の順に移動、選択します。

### 問題: gpt-5.4-mini のデプロイが ARM テンプレートのデプロイ中に失敗する
**解決策:** サブスクリプションで Azure OpenAI のクォータを調べます。 このモデルには少なくとも 20 TPM の容量が必要です。 必要な場合は、クォータの増量を要求します。

## タイムライン概要

| Event | 時間 | アクション |
|-------|------|--------|
| T+0 時間 | ARM テンプレートをデプロイする | Azure portal から lab-3d-setup.json をデプロイする |
| T+15 分 | AI 用 Defender を有効にする | Defender for Cloud で自動的に有効になっていない場合は、手動で有効にする |
| T+20 分 | コンテンツ フィルターの状態を確認する | gpt-5.4-mini にカスタム フィルターが適用されていないことを確認する |
| T+25 分 | 敵対的トラフィックのスクリプトを実行する | generate-adversarial-traffic.ps1 (15 件のクエリ、約 15 秒) |
| **T+24 時間** | **検出結果を確認する** | **2 件以上の検出結果について、[Defender for Cloud] > [データと AI セキュリティ] を確認する** |
| T+36 時間 | 必要に応じて再実行する | 検出結果が 2 件よりも少ない場合は、スクリプトを再度実行し、さらに 12 時間待つ |
| T+48 時間 | 環境準備完了 | ラボ提供準備完了としてマークする |

## 重要な注意点

- **sc500-lab3d-foundry にコンテンツ セーフティ ガードレールを適用しないでください** - これを行うと、Defender が攻撃を検出できなくなります
- **レート制限を適用しないでください** - ラボ シナリオでは、エンドポイントは完全に非保護状態である必要があります
- **サブスクリプション キーの要件を適用しないでください** - 受講者が非保護のエンドポイントを確認できる必要があります
- **24 時間以上のリード タイムは絶対条件です** - AI 用 Defender での動作分析には時間が必要です
- **AI 用 Defender を有効にした後に敵対的スクリプトを実行してください** - 検出結果は遡って表示されません
